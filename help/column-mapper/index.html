Any other exchange: the column mapper

Import any CSV, Excel sheet or zip by telling TaxFlow what each column means, check a dry run, and save the mapping to reuse.

Updated 17 October 2026Column mapper

On this page

  1. Open the mapper
  2. The seven steps
  3. Reusing and sharing mappings

Follow along in the app. Your files stay on your device.

Open the app

For any exchange, wallet or spreadsheet TaxFlow does not recognise (Independent Reserve, Digital Surge, Cointree, Bybit, Bitget, a block explorer export, or your own records), the column mapper turns it into transactions. You tell it which column is the date, the amounts, the assets and the type of each row. It shows a dry run before anything is imported, and it saves your answers as a mapping that is offered again for the next file with the same columns.

Open the mapper

  1. Open Import and add the file. CSV, TSV, text, .xlsx (each sheet is an entry) and .zip all work.
  2. If TaxFlow does not recognise it, choose Any other CSV, XLSX or zip as the exchange.
  3. Select Map columns. You can also start from a preset (Independent Reserve, CoinJar, Koinly universal), which fills in a starting point for you to check.

The bottom of the mapper always shows the first five data rows, so you can see what you are mapping. That preview stays on your device.

The seven steps

1. Header row

Which row holds the column names. Row numbers start at 1. Title rows and notes above the header are kept out of your transactions.

2. Row shape

Shape Use when Example
Sent and received amounts Each row is one whole transaction: what went out and what came in Koinly template, CoinJar
Ledger Each row is one asset moving in or out; a trade is two or more rows Independent Reserve, Kraken-style ledgers
Trade fill Each row is a fill with a pair, a side and a quantity Most exchange "trade history" files

In the sent and received shape, a row with only a received amount is a deposit, only a sent amount a withdrawal, and both a trade. In the ledger shape, the rows of one trade are grouped by a group id column if you map one, otherwise by being in the same second.

3. Columns

Map each field to a column. Required fields are marked. Optional ones that help a lot: value_aud (saves entering values for swaps), fee_amount and fee_asset, native_id (keeps ids stable and catches duplicates), and tx_hash (helps match transfers to your other wallets).

4. Transaction types

Every distinct value in your type column is listed with how many rows have it and sample line numbers. Map each one to a kind: trade, deposit, withdrawal, income (staking, interest, reward, mining, other), airdrop, fee, gift_out, spend, ignore, or unsupported. Anything you leave unmapped becomes an unsupported row, never a guess.

5. Dates and numbers

Confirm the date order (day/month/year is usual in Australia; a US export may be month/day/year) and the time zone the file was written in. If the dates carry an offset, choose from-value. Set the decimal and thousands separators, and tick the options to strip currency symbols or read amounts written like 0.5 ETH. You must tick I have checked the date order and export time zone before you can save.

6. Fees and filters

The fee mode is how the fee relates to the amounts:

  • Fee deducted from received amount: the received amount in the file is before the fee.
  • Fee in addition to sent amount: the fee was charged on top of what you sent.
  • Fee included in sent amount: the sent amount already includes the fee.

Check one transaction where you know the real numbers. You can also set a default wallet and fee asset, and add ignore filters (a column and a pattern) for rows such as subtotals.

7. Dry run

Counts per kind, and per asset the total in, total out and the resulting balance. Negative balances are highlighted: usually a missing earlier file, a sign the wrong way round, or a type mapped to the wrong kind. Name the mapping and choose Save mapping and import.

Reusing and sharing mappings

Saved mappings appear under Saved column mappings on Import. When you add a file with the same header (or nearly the same, with every mapped column present), TaxFlow offers Use saved mapping. You can export a mapping as JSON and import it elsewhere. A mapping holds headers and rules only, never transaction rows, but it does include any default wallet name you typed, so check that before sharing.

Check

a mapper import is only as right as the mapping. Compare the dry run's closing balance for each coin with the balance the exchange shows for the same date before you save.
