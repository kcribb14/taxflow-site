BGL Simple Fund 360 export

Create the BGL File Import XML for your fund's crypto, test it in a sandbox fund, and know what it posts and what it leaves out.

Open the app

BGL Simple Fund 360 (SF360) has no plain CSV import for crypto trades. Its route for transactions from other systems is the BGL File Import feed, which takes an XML file built to BGL's official Excel (XML) import template. TaxFlow writes that XML directly, so you do not need the Windows Excel macro workbook.

Check

the XML's structure is checked field by field against BGL's official template (51 fields, in BGL's order). Whether a live SF360 fund accepts it and posts it exactly as intended has not been verified. Import it into a sandbox or test fund first, check the postings, and only then import into the real fund.

Before you start

  • The project's Taxpayer is SMSF in Settings. The SMSF files appear on Reports only then.
  • Review is clear for the year. The BGL files refuse to build while the year has a missing AUD value.
  • 30 June prices are entered in Holdings for every coin held, if you want the price file.

Download the files

On Reports, pick the tax year, then in SMSF files download:

File Use
bgl-transactions.xml The file to import through BGL File Import
bgl-transactions.csv A compact worksheet of the same rows, for checking or copying by column header
bgl-prices.csv 30 June price of each coin held, to key in as a custom price
rounding-residual-bgl.csv Units lost when rounding to BGL's 6 decimal places, per coin

Each file lists notes beside it. Read them: they name anything unconfirmed in your particular year.

Import into SF360

In SF360, set up the feed: Connect, then Feed Management, then Wraps and Platforms Global, and add a feed with Feed Provider BGL File Import and Account ID BGL. Choose the fund's default bank account and, if useful, a "do not import data before or after" date. Then upload the XML. These are BGL's documented steps; your administrator may already have the feed set up.

How each transaction is written

In TaxFlow In the BGL file
Buy with AUD Investment Transaction, positive amount = cost base including fees, with quantity; the fee is repeated in Brokerage
Sell for AUD Investment Transaction, negative amount = proceeds less fees
Swap A disposal row for the coin given up and an acquisition row for the coin received, both at market value
Staking or other income An Income Transaction (credit) plus an Investment Transaction for the units at the same value
Airdrop or gift received Investment Transaction at market value
Chain split or initial allocation Investment Transaction at 0.00
Spend or gift given Investment Transaction, negative, at market value
Network fee paid in crypto Investment Transaction, negative, described "Network fee"
Transfer between the fund's own wallets Not written (holdings do not change)

Coins use Security Type Cryptocurrency and a code of the asset plus .COIN (for example BTC.COIN), which is how SF360 recognises crypto and links its daily price feed. Codes are cut to 15 characters; dates are DD/MM/YYYY; amounts are to the cent; quantities to 6 decimal places.

What is not included, and the unconfirmed points

  • AUD bank legs. Cash in and out comes from the fund's bank feed. Adding bank rows as well could double count.
  • Opening balances. Coins held before 1 July of the exported year are not written. If the fund is new to SF360, its opening parcels need entering separately.
  • Brokerage. Whether SF360 expects the amount to include brokerage is unconfirmed; TaxFlow includes it, which matches BGL's broker import.
  • Staking pairs. BGL does not document pairing an income row with an investment row for staking. Check the posting after your test import.
  • Zero amounts. SF360 may reject a 0.00 row for a fork or initial allocation.
  • Rounding. A tiny holding can round to 0.000000 at 6 decimal places. The residual file shows the difference.
  • Repeat imports. Transaction ids are fixed for the same data, so do not import overlapping years twice.

Other feeds

Some exchanges (for example Swyftx and Digital Surge) offer their own data feeds into SF360. If the fund already receives one, do not import the same trades through TaxFlow too.
